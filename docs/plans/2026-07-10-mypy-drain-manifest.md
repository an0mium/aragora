## Drain Rules

1. Do not create another mypy repair PR while the open repair count exceeds 10.
2. Claim a lease before restacking or pushing an existing branch; skip fresh active owners and unread steering.
3. Merge current `origin/main` normally; never rewrite a published mypy branch.
4. Reproduce a current-main before/after identity proof with hashes and zero additions before evidence or readiness.
5. One repair maximum per PR. Fresh dissent after that repair parks the PR for human disposition.
6. Tier 3/4 settlement and any incident waiver remain exact-head human decisions.

## Data Sources

- Open PR metadata, bodies, comments, and changed-file sets from the GitHub REST API.
- Current-main distance from GitHub compare API (`PR head...origin/main`).
- Tier, required-check state, mergeability, dissent, and live blockers from batched `review-queue merge-packet --ignore-own-quorum-check`.
- Ownership/activity from the latest matching agent-bridge lane row; active rows are blocking only while their heartbeat/update is fresh.
- Identity-proof classification is conservative: incomplete or unbound claims are parked, never promoted.
