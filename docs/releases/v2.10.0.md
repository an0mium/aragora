# Aragora v2.10.0

**Target release:** 2026-09-04, on the operator's `v2.10.0` tag
**Previous stable:** v2.9.0 (2026-04-25, sha `1e3ce85ae6`)
**Release-candidate predecessor:** none (cut directly from `main`; see "Reviewed design tradeoffs" in the release PR)

## Headline

The dissent-preserving Decision Receipt is now load-bearing end to end. A PR review run through `aragora review` produces an Open Decision Receipt (ODR), the receipt can be signed with a detached Ed25519 signature and served with its public key, and a stranger can verify it offline with the standalone `aragora-verify` package or with the in-package `odr_verify` engine. The GitHub Action emits the same receipt as a PR artifact.

Alongside the receipt path, merge-gate disagreement is now published as data: Disagreement Atlas v1 (`docs/atlas/`, release `atlas-v1`) records every counted reviewer verdict, adjudication and vindication across the merge quorum, and the receipt-first scoreboard (`scripts/receipt_first_scoreboard.py`) measures the ten exit metrics that the Receipt-First mission is held to.

This release carries 1,862 commits since v2.9.0. It is cut directly from `main` without a release-candidate tag because every one of those commits already landed behind the required check set (lint, typecheck, sdk-parity, Generate & Validate, TypeScript SDK Type Check, aragora-merge-quorum).

## Upgrade notes

### From v2.9.x

No mandatory migration steps. The Python public API is additive. After the tag is cut:

```bash
pip install --upgrade aragora
python -c "import aragora; print(aragora.__version__)"   # 2.10.0
```

To verify receipts offline, install the standalone verifier alongside it:

```bash
pip install aragora-verify
aragora-verify --help
```

### Receipt producers and consumers

- `aragora review` and the GitHub Action now emit ODR documents; signing is opt-in and requires a configured Ed25519 key (`ARAGORA_ODR_SIGNING_KEY_SECRET` or the secrets-manager path). Unsigned receipts remain valid ODR documents.
- Receipt schema 1.3 adds optional planning-evidence bindings; consumers that ignore unknown members are unaffected.
- `DecisionReceipt` verdicts are never minted from zero evidence (#9306). Pipelines that relied on an empty-evidence PASS will now see a non-passing verdict.

### Model defaults

Runtime defaults moved to the current frontier models (Claude Fable 5 / Opus 5, GPT-5.6 Sol, Kimi K3, Qwen 3.8 Max). Pin `model=` explicitly where a fixed model matters; the canonical catalog (`aragora/models/`) is the single source for names and pricing.

### npm consumers

`aragora/live`, `sdk/typescript`, `ide/vscode-aragora`, `examples/sveltekit` and `docs-site` carry refreshed dependency pins; re-run `npm install` after pulling.

## Known issues / deferrals

- **`release.yml` `validate` job:** the tag-push workflow has failed its `validate` job on every tag push to date; PyPI 2.9.0 was published by `publish-aragora.yml` (`workflow_dispatch`). The same path is used for 2.10.0; `release.yml` is recorded, not required.
- **Whole-tree mypy:** `mypy aragora/` reports 1,744 errors on `main` and `make ci-required` is red; CI masks it and the mission gate only forbids growth.
- **Hosted API:** `api.aragora.ai` does not answer from outside; the canary answers 200. Cutover is an operator act tracked in #9391.
- **Postgres migrations** fail with an `AUTOINCREMENT` syntax error at `aragora/migrations/runner.py:271` (SQLite-only DDL), and the backend Docker image cannot import its installed dependencies at runtime (#9955). Both are scheduled for the hosted-receipts milestone.
- **Import cycles:** 138 remain (ceiling 140); the `review_queue↔review_queue_{render,unstable}` pairs are Tier 4 and untouched.
